# Contributing to Perles

Thanks for contributing to Perles.

This file is a routing guide for contributors. Canonical commands and workflows live in `docs/`.

## Start Here

1. Fork the repository.
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/perles.git`
3. Create a branch from `main` (for example, `feat/...`, `fix/...`, `docs/...`).
4. Make your changes.
5. Run the relevant validation from [docs/TESTING.md](docs/TESTING.md).
6. Open a pull request using the repository template.

## Canonical Contributor Docs

- [docs/CODING.md](docs/CODING.md) — build commands, codebase layout, and coding conventions
- [docs/TESTING.md](docs/TESTING.md) — required test/lint commands and golden-file workflow
- [docs/PULL-REQUESTS.md](docs/PULL-REQUESTS.md) — branch strategy, PR expectations, and review readiness
- [docs/RELEASING.md](docs/RELEASING.md) — release pipeline and pre-release checks

## Reporting Issues

Use GitHub Issues for bug reports and feature requests. Please include:

- Perles version (`perles --version`)
- Go version (`go version`)
- Operating system and terminal
- Steps to reproduce (for bugs) and expected behavior

## Questions

Open a GitHub issue or discussion if you need help choosing an approach or validating scope.
